# Support operations change — Firestore access findings

Created while implementing the operations-support feature.  This document is
not deployed and records the access paths used to review the prototype rules.

* `users/{uid}` is private and client list queries are denied; support-user
  discovery must therefore be a callable that returns a deliberately small
  display projection.
* `chat_rooms/{roomId}` is readable only by `participantIds` members and room
  creation is already server-only.  Support rooms use the same participant
  model and are created only by callables.
* Existing `app_inquiries` and `app_issue_reports` are client-created.  New
  submissions are moved to an App-Check callable so the case record, support
  room and delivery message commit atomically.  Rules retain a legacy create
  path only when no follow-up field is supplied.
* `publicProfiles/{uid}` is authenticated get-only.  Operations accounts are
  excluded from this projection and recommendation serving performs a second
  `accountType` check before rendering stale recommendation items.
* The `admin/{uid}` document is metadata only.  Both its existence and the
  Firebase Auth custom claim `operations: true` are required by operations
  callables.  Firestore client reads and writes are denied.
