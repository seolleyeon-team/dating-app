## 2. P1-13 — implementation

- `seasonMeetingAuthority.ts`: transactional context loader (match contract,
  room, active promise, lock, phase), partition check, team-leader check,
  captured-deposit read; pure decisions `decideNoShowReport`,
  `deriveCancelWindow`, `evaluateSchedule`.
- `seasonMeetingScheduleLock.ts` + `onSeasonMeetingPromiseWritten`
  (`retry: true`, reads current state, idempotent; non-season rooms return
  immediately).
- `seasonMeetingOperations.ts`: every decision inside one transaction;
  no request field is authoritative (source-scan test); report id =
  digest(meeting, reporter, accused, category) created once; cancellation
  only by a team leader, window from phase + observed schedule + server time
  (KST calendar day = `day_of_meetup`), deposit capture from the ledger,
  decision + deterministic audit + transition in one commit, retries return
  the decision, nobody replaces it; intent id = digest(uid, meeting,
  validated key), server amount/currency, `create()`, one open intent per
  participant and meeting, intent + `deposit_pending` in one commit; refund
  transactional, owner-only, after capture, amount granted by the cancel
  decision, applied once; same-phase transitions write nothing.
- Product decision recorded: no individual-withdrawal lifecycle exists for
  season meetings, so an ordinary member's whole-meeting cancellation is
  refused (FSM actor `leader` already modelled). **Owner to confirm** the
  leader rule before the feature is released (`kSeasonMeetingReleased=false`).
