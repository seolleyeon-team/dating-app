## Batch 001 ownership proof

The ten approved files are pytest `*current` pointer outputs. They contain only local absolute paths into the same test-output directory. They are not source-of-truth files, test fixtures, golden assets, deployment inputs, or runtime resources. The test suite recreates its own temporary files using `tmp_path`; no test reads these checked-in pointers.

Equivalent regeneration command:

```powershell
.venv\Scripts\python.exe -m pytest tests\test_avatar_qa_cleanup.py -q --basetemp pytest_tmp_avatar_qa_escalated
```

The command is an equivalent generator path, not a claim that the exact historical bytes or absolute paths will be identical.

## Deferred test outputs

The 34 PNG files are synthetic inputs/outputs produced by `_pattern_image`, `_other_pattern_image`, and `_save_png` in `tests/test_avatar_qa_cleanup.py`. They include intentionally corrupt/blank/identical/low-quality candidate cases and must not be confused with production avatar media. They are deferred only because exact historical basetemp reproduction and deletion verification have not yet been run.

`ttl_report.json` is generated by the TTL cleanup test at `tests/test_avatar_qa_cleanup.py:930`; it is also deferred until its exact report role and regeneration evidence are recorded.

## Protected classes

Keep without additional owner proof:

- audit/operational reports and incident evidence;
- migration, repair, backfill, or release inputs/outputs;
- source-like `.py`, `.cjs`, `.dart`, `.ts` files under `.tmp`;
- token, consent, mapping, App Check, or privacy evidence;
- golden/fixture files and assets consumed by tests;
- `festival_web/**` and prototype/design projects;
- any path with unknown generator, source-of-truth, or release/CI consumer.

Only exact paths with a concrete generator, zero runtime/operational consumers, backup evidence, and Reviewer A+B approval can move to `SAFE_TO_REMOVE_CONFIRMED`.
