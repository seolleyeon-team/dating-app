# Full file inventory companion

This document is the human-readable index for `docs/dead_code_cleanup/full_file_inventory.csv`.

- Tracked rows: 18,150
- Worktree existence, size, top-level area, extension, heuristic classification, workflow relation, runtime-protection status, history presence, and audit notes are included in the CSV.
- The CSV was generated by `scripts/audit/generate_dead_code_inventory.ps1` from the current repository and includes all tracked paths, including separate projects and artifact-heavy areas.

## Interpretation rules

1. `GENERATED_OR_ARTIFACT` is a triage label, not permission to delete.
2. `UNCERTAIN_OR_SEPARATE_PROJECT` is preserved by default.
3. `RUNTIME_OR_PLATFORM`, `OPERATIONAL_OR_PIPELINE`, `TEST`, and workflow-linked rows remain protected until their references are audited.
4. A `no-history-found-in-all-refs` status is not a dead-code result.
5. The current user WIP and denied `.tmp` paths are preserved.

## First-party review scope

The next reference-review pass must inspect, at minimum, `lib/**`, `functions/src/**`, `test/**`, `tests/**`, `rules_tests/**`, `android/**`, `ios/**`, `web/**`, `assets/**`, `scripts/**`, `tools/**`, `infra/**`, root Firebase configuration, CI, and documentation/runbook files. `festival_web/**`, `tmp/**`, `.tmp/**`, prototype directories, and generated/vendor areas need an owner-specific audit instead of bulk removal.

See `02-full-file-inventory.md` for counts, boundaries, and limitations.
